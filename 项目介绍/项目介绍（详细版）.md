## 一、项目名称与简介

- **项目名称**：内网终端安全基线管控与数据汇聚平台（网络信息采集和端口管理工具）
- **项目类别**：技术改造 / 自研工具类
- **适用范围**：单位内网办公终端、服务器、专用设备（Windows 10 / Windows 11 / Windows Server，64 位）
- **一句话简介**：把"终端安全自查、漏洞封堵、整改跟踪、数据汇总"四件事从人工搬运变成自动执行——一台终端装上即用，管理员在一块大屏上看到全网暴露面。

## 二、项目背景与要解决的实际问题

内网终端数量多、分布散、操作系统与业务软件版本不一，长期依靠"人工巡检 + 表格汇总 + 逐台整改"开展安全自查，存在四个突出痛点：

1. **查不全**——84 个高危端口的封堵状态、主机名、硬件序列号、登录用户等信息散落在各台机器上，人工记录既慢又易漏项。
2. **改不快**——发现 SMB、NetBIOS、RDP 等端口对内网开放后，仍需逐台登录、逐个手动调整，处置周期长。
3. **看不清**——整改结果汇总成 Excel 再人工统计，无法实时掌握"全网还有多少台暴露、暴露在哪个端口、风险有多高"。
4. **推不动**——依赖"目标机器能主动访问中心服务器"的老办法，在无出网权限、跨网段、终端不主动外联的环境里直接失效，数据长期收不回来。

> 一句话概括痛点：不是"没有工具"，而是"工具只能在理想网络条件下用，且查完之后的汇总仍靠人"。

## 三、总体设计

围绕"摸清家底 → 快速整改 → 自动跟踪 → 数据可视"闭环，自主研发**终端侧 + 服务端**双端工具：终端零配置即用、服务端零依赖即部署、整改结果自动回流、管理员一块屏掌握全局。

```
终端层   网络信息采集和端口管理工具（单文件 EXE，管理员权限）
         安全总览与高危端口体检 / 5 套预置封堵策略 / 共享与服务加固 /
         IP 白名单 / 端口转发（445→10001）/ 受控远程桌面（内嵌 SubnetDesk）
   ↓ 采集快照（本机缓存，间隔自动刷新）
发现层   局域网代理：UDP 18762 广播身份（PST-DISCOVER-V1）+
         TCP 18762 只读拉取接口（/pst/v1/device），启动即自动放行防火墙入站规则
   ↓ 服务端主动扫描发现 → 主动拉取（终端无需外联，跨网段可用单播探测）
服务端层 PST 终端安全运营中心（Node 22 单文件 EXE / 零外部依赖 / 内置 SQLite）
         三路并行扫描发现 → 定时拉取入库 → 主机与快照建模 → 汇总统计与离线判定
   ↓ 只读接口（JSON）
展示层   数据大屏：终端态势总览、风险分布、24 小时采集趋势、暴露端口 TOP、
         主机清单、单机详情（84 端口暴露矩阵 + 采集历史）、客户端发现与拉取模块、系统设置
```

### 关键设计取舍：把"客户端上报"改成"服务端主动拉取"

初版沿用"终端定时 POST 到中心"的思路，实测暴露出致命问题：**只要终端没有到中心的网络路径、或中间设备拦截了出站，数据就永远收不到**。为此重新梳理数据链路，改为**服务端主动发现 + 主动拉取**：

- 终端不再外联、不再依赖中心地址，**默认开启**局域网代理并在启动时自动添加入站放行规则；
- 服务端发现采用**三路并行**：UDP 全局广播 + 各网卡定向广播、网段内逐地址 UDP 单播探测、TCP 18762 端口探测（免令牌 ping），任一路命中即视为发现；
- 跨网段场景可在扫描框直接指定网段（如 `192.168.1.0/24`），不依赖广播转发；
- 令牌双向一致校验；终端未配置令牌时也可免令牌拉取，便于快速试点。

改造后单次全网扫描稳定在 **2.2 秒**量级完成（改造前依赖广播时经常"扫不到"），定时拉取保证数据新鲜度。

## 四、主要创新点

| 序号 | 创新点 | 技术做法与价值 | 类型 |
| --- | --- | --- | --- |
| 1 | 三路并行局域网发现 | UDP 广播 + UDP 单播 + TCP 端口探测同时进行，规避广播被拦截、跨网段广播不通两大顽疾；无需安装任何客户端插件即可发现 | 架构 |
| 2 | 单向拉取数据模型 | 终端只开放只读拉取接口、服务端定时主动取数；终端不外联、不暴露写接口，符合内网最小暴露原则 | 架构 |
| 3 | 零依赖单文件交付 | 客户端 90.7 MB 自包含 EXE（含 .NET 运行时），服务端 57.7 MB 单 EXE（内置 SQLite）；目标机无需预装 .NET、Node、VC++ 运行库 | 工程 |
| 4 | 84 端口策略化封堵 | 沉淀为 5 套场景化策略（防勒索加固、远程入口封堵、弱服务收敛、数据库暴露面收敛、一键全量），一键执行、逐条可回滚 | 业务 |
| 5 | 风险量化与闭环看板 | 按暴露端口、严重暴露数、封堵率自动生成 0–100 风险分与高/中/低三档等级，支撑"整改前—整改后"对比 | 业务 |
| 6 | 内置受控远程桌面 | 内嵌 SubnetDesk 便携包，必须由被控端本机用户人工确认、仅对请求方单个 IP 临时放行，用完即恢复 | 安全 |
| 7 | 自检机制保障可维护 | 内置功能自检程序（29 项断言）与界面自检探针，改完即回归，工具自身可验证 | 工程 |

## 七、效益分析

**管理效益**
- 把"季度人工抽查"变成"日常自动巡检"，管理员每天在屏幕上即可看到全网暴露面与离线主机，异常项自动置顶。
- 统一口径替代多头统计：终端、科室、大屏三处数据同源同构，报表不再需要二次加工。
- 整改过程可追溯：单机详情保留历次采集快照与风险分变化，印证"封堵前—封堵后"效果，支撑安全考核与责任落实。

**安全效益**
- 84 个高危端口逐端口可见，从"装过补丁就算合规"转为"逐端口可验证"，压缩 SMB、NetBIOS、数据库、远程桌面等入口暴露面。
- 远程桌面等高风险能力一律"用完即还原"，杜绝长期开放管理端口形成新攻击面。
- 数据链路改为服务端主动拉取后，终端不再需要出网权限，也不再存在对外暴露的写入接口，横向移动风险降低。

**经济效益**
- 零采购：不需要商用终端管控软件、服务器数据库或中间件授权，也不占用额外服务器资源（单进程 + 单文件 SQLite）。
- 人力替代：以 200 台终端、年 4 轮巡检估算，仅"逐台核对端口与设备信息"一项即可替代约 **400 人时**的人工投入（按 30 分钟/台计），人力可转向分析研判。
- 复用现有资产：远程桌面复用内嵌 SubnetDesk 便携包，不额外采购第三方远程工具。

**推广价值**
- 已沉淀为**可复用的交付形态**：源码 + 单文件成品 + 使用文档 + 自检程序，可直接复制到其他科室、段（局）乃至上级单位。
- 数据契约（`port-security-tool.device-report / v1.0`）公开、字段只增不改，可平滑接入单位既有安全平台或数据中台。
- "发现端口 + 拉取令牌 + 网段指定"三项可配置，适配多网段、多安全域并存的复杂内网环境。

## 九、技术特点与自主性说明

- **完全自主开发**：客户端（C# / .NET + WinForms + WebBrowser 混合宿主）与服务端（Node.js + 内置 SQLite + 原生前端）全部自研，无第三方商业组件与闭源 SDK。
- **零外部依赖**：服务端不依赖任何 npm 运行期库，客户端不依赖目标机 .NET 运行时与 VC++ 运行库，便于在老旧终端上推广。
- **数据契约稳定**：报文结构以 JSON Schema 固化并随工具提供，字段只增不改，服务端可长期解析。
- **安全合规**：仅在本单位内网使用，所有加固动作可回滚，采集数据按内部数据分级要求存储与使用。

> **关于文中截图**：截图取自单位内部真实运行界面（含主机名、IP、序列号、MAC、设备 ID 等），仅用于内部申报材料；如需对外发布或跨单位共享，须先对上述字段做脱敏。
